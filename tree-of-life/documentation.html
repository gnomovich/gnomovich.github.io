FamilyTree — user manual

Version 1.1.0 · Windows 10/11 · written for the person doing the research.

1. What FamilyTree is

FamilyTree is a desktop application for keeping a family tree and reading it. It opens a single SQLite database that lives in Documents\FamilyTree\, draws the people around a central person as a fan chart, and offers a table, two tree layouts, statistics, a timeline and a places list for the same data.

Three ideas shape the whole application:

  • Local and private. There is no account, no server and no telemetry. The database and the photographs are files on your computer.
  • Editing is first-class. People, names, relationships, events, places and documents are edited inside the app, not in external tools.
  • Nothing is lost. Before any destructive action the app writes a full snapshot to backups\, and everything can be exported.

2. Installing and first run

  1. Download FamilyTree_1.1.0_x64_en-US.msi from the overview page and run it.
  2. The installer is not code-signed, so Windows SmartScreen may ask for confirmation: choose More info → Run anyway.
  3. Start FamilyTree from the Start menu.

On first run the app creates the data folder and an empty database:

  • %USERPROFILE%\Documents\FamilyTree\familytree.db — the database
  • familytree.db-wal, familytree.db-shm — SQLite write-ahead log
  • media\ — photographs and documents
  • backups\ — automatic snapshots
First time? You can start from nothing (press New person) or import an existing GEDCOM file — see GEDCOM import and export.

3. The window at a glance

  • Controls (left) — central person search, number of generations, fan opening angle, rotation, sector spacing, zoom, the View selector, colouring mode, checkboxes for dates/places/gaps/abbreviated names, and the buttons Recentre, Save PNG and New person.
  • Chart (centre) — the fan chart, the table, the trees or one of the full views. The status line at the bottom shows the version and the number of people.
  • Person panel (right) — everything known about the selected person. It opens when you click a sector, a row or a person; × closes it.
  • Settings (⚙, bottom-left) — databases, GEDCOM, exports and language.

4. Moving around the fan chart

The fan chart shows the ancestors of the central person: each ring is one generation. The centre is the person, the inner ring the parents, then grandparents, and so on.

  • Zoom — mouse wheel, or the Zoom slider. The percentage is shown next to it.
  • Pan — drag with the left mouse button.
  • Open a person — click a sector; the person panel opens and the fan re-centres on them.
  • Search — type in Central person and pick a result; the fan re-centres.
  • Appearance — Generations (1–8 rings), Fan opening (60–360°), Rotation, Sector gap, colouring by surname or birth place, and the four display checkboxes.
  • Save PNG — writes the current chart as an image.
The fan chart is a picture of ancestors. Descendants are shown in the descendants view.

5. The person panel

The panel is the record view. From top to bottom: the name and years, quick actions, the details, the relatives, the events, the photographs and documents, the places and the notes.

  • Centre here — makes the person the centre of the chart.
  • Edit — opens the editor for names, sex, living status and notes.
  • Parents, Spouses, Siblings, Children — click a name to open that person, × to remove the relationship.
  • Events — every event with date and place; the document icon marks events that have a record attached.
  • Photographs / Documents — see the media section.
  • Warnings — non-blocking checks such as a death before birth or a parent younger than 13.
  • Possible duplicates — similar names and dates; clicking one merges the other person into this one, and the app offers to undo.

6. Creating and editing people

  • New person (controls, bottom-left of the button row) — creates a person with no relationships; you can link them afterwards.
  • Edit (panel) — changes the name, sex, living status and notes.
  • Delete (inside the editor) — only allowed when the person has no relationships; the app explains what to remove first.

Names are stored whole and also split into given name and surname, which is what the surname colours and the table filters use. The full name is always what you see in the chart and the panel.

7. Relationships

Use the buttons under the quick actions: Add parent, Add child, Add spouse. Each opens the person picker:

  1. Search for the person — or press Create new person and fill the form; the new person is linked straight away, without a second search.
  2. Relationships are validated: the app refuses a link that would create a cycle or a third parent.

Siblings are derived, not stored: two people are siblings when they share at least one parent, which includes half-brothers and half-sisters. Families that describe the same couple are merged automatically so siblings always appear.

8. Events and dates

Each event has a type, a genealogical date, a place, an optional description and notes. Types: birth, baptism, death, burial, marriage, residence, occupation and other.

9. Photographs and documents

The panel has two sections, Photographs and Documents. Both hold image files copied into the media\ folder next to the database.

  • Add — Add photograph… or Add document… opens the file dialog; you can select several files. Files are copied with their original name (-2, -3 on collision).
  • Open — click an entry to open the full-screen viewer: wheel to zoom at the cursor, drag to pan, Fit, 100%, Rotate, brightness and contrast sliders (screen only — the file is never modified). Esc closes it.
  • Edit — the pencil changes the type (photograph or document), the title, the caption, the archive reference (for example LMG14-001-0001_m0074) and the event the record proves.
  • Several people — Link person… associates the same record with another person (a marriage certificate serves both spouses) and × removes that link. A record always keeps at least one person or an event.
  • Events — a document linked to an event also appears inside that event's editor, and the event row in the panel shows a document icon.
Formats. Only images the viewer can show are accepted: JPG, PNG and WebP. TIFF and PDF files are not supported — convert them before adding.
Duplicates. Each file is identified by its SHA-256 hash: adding the same scan twice does not create a second copy, it just links the existing record.

10. The other views

Everything is an option of the View selector; closing a view returns to the fan chart.

  • Table — the person list with filters (name, surname, sex, living/deceased, birth place) and sortable columns; a click opens the person.
  • Pedigree — ancestors to the right, 2–6 generations, drawn as plain SVG with zoom, pan and click-to-recentre.
  • Descendants — one row per generation, 3, 5, 8, 13, 21 or 34 generations; siblings stay side by side even when one has a long line.
  • Statistics — totals, oldest/newest, average age at death, endogamy (siblings and 1st–4th cousins), surnames, births and deaths per decade, birth places and data gaps.
  • Timeline — every dated event by decade or by year, stacked by type.
  • Places — events and people grouped by place, filterable and sortable.

11. Settings: database and language

The gear at the bottom-left corner opens the settings window.

  • Base de dados / Database — the file in use, the recent list, Abrir… to open an existing database, Novo… to create an empty one. Switching reloads the tree, panel and counts without restarting; the last database reopens next time.
  • Idioma / Language — Portuguese or English. The whole interface is retranslated immediately, including the window title; the choice is remembered.
  • Exportar GEDCOM… / Importar GEDCOM… and Exportar tudo… — see below.
  • Abrir pasta de dados — opens the data folder (useful to reach backups\ or media\).

12. GEDCOM import and export

Export

Exportar GEDCOM… writes the open database as a standard GEDCOM 5.5.1 file (people, families, names, events, dates and places), suggested with the database file name.

Import

Importar GEDCOM… asks where to put the data: into the open database or into a new file created on the spot. People who already exist (same name and birth year) are skipped and the imported families are pointed at the person already in the database, so importing the same file twice changes nothing. At the end a summary reports how many people, families, events and places were added, and any warnings.

When the database still has no central person, the first person in the file becomes the root — usually the one the source program lists first. Importing into a database in use does not change the current centre.

13. Exporting everything

Exportar tudo… writes a single .zip with:

  • dados.json — every table of the database, in readable JSON;
  • arvore.ged — the same data as GEDCOM 5.5.1;
  • media\ — every photograph and document file.

This is the recommended archive for a finished piece of research, and the easiest way to move a tree to another computer.

14. Backups and your data

  • Before any destructive action the app writes a full copy to backups\familytree-AAAAMMDD-HHMMSS.db and keeps the last 10. There is no restore screen: copy a snapshot back over familytree.db with the app closed.
  • The snapshots cover the database only. The unit to back up is the whole folder — familytree.db plus media\ — or the zip from Exportar tudo….
  • Do not keep a live database inside OneDrive, Google Drive or Dropbox: synchronising a database while it is open can corrupt it. Work locally and let the synced folder hold the exported zips.

16. Troubleshooting

"Database schema incompatible"

The file was written by a newer version of the app. Update FamilyTree, or open a copy with the version that created it.

A photograph shows a broken icon

The record exists but the file is missing from media\. Put the file back with the same name, or add the image again (the hash keeps the same record).

The app feels slow on a big database

Opening a view reads the whole database once. Keep the database outside synced folders and avoid opening it twice; the table is paginated and the views show "loading" only when a query takes longer than 300 ms.

I deleted a person by mistake

Close the app and copy the most recent file from backups\ over familytree.db. You lose the changes made after that snapshot.

SmartScreen or antivirus warnings

The installer is not signed yet; choose More info → Run anyway. If your organisation blocks unsigned installers, ask your administrator for an exception.

17. Feedback and help

Suggestions, bugs and missing features are welcome — please use the feedback form. When reporting a problem, mention the version, what you were doing, and whether the database came from a GEDCOM import.
